# TI2V skill optimization and task-grounded repair

This directory collects our exploration of SkillAdam for text-and-first-image video generation and the task-grounded relation repair developed alongside it. The completed integration runs the pinned SkillAdam optimizer on reusable robot-video skills. A crossed experiment combines its frozen skill with PhiAgent contact-event sampling. The current candidate instead targets generation prompts through small, evidence-bound relation edits.

Start with [SKILLADAM_EXPLORATION.md](SKILLADAM_EXPLORATION.md) for the integration, accepted updates, crossed ablation, and proposed composition with relation repair. [METHOD.md](METHOD.md) describes the repair algorithm and its comparison with VideoWeaver. [RESULTS.md](RESULTS.md) contains the full metric tables and negative results.

The SkillAdam adaptation completed two optimization rounds and all 60 final outputs. Both updates passed their small validation batches; the final results did not outperform VideoWeaver across all five metrics. The relation-repair experiment is now fully scored: its primary raw-output comparison raises dyn but lowers the other four metric means, and all five 99% intervals include zero. See [PAIRED_RESULTS.md](PAIRED_RESULTS.md) for the complete result.

## Code entry points

| Path | Role |
|---|---|
| `scripts/run_ti2v_skill_optimization.py` | Pinned SkillAdam full loop and a separately identified bounded PhiAgent optimizer |
| `integrations/skilladam_ti2v/adapter.py` | TI2V domain registration, official metric parsing, and five-metric update acceptance |
| `integrations/skilladam_ti2v/backend.py` | Remote generation, original five video gates, selection, scoring queue, and tool transport |
| `method.py` | Public relation-repair proposal entry, literal task preconditions, and decision artifacts |
| `integrations/skilladam_ti2v/relational_repair.py` | Evidence bindings, relation templates, and bounded text compilation |
| `integrations/skilladam_ti2v/repair_factorial.py` | Joint/factored decisions crossed with original/extended relation vocabularies |
| `phiagent/harness/video_meta_rsi.py`, `video_pareto_rsi.py` | Bounded skill and policy optimization with acceptance and fallback |
| `scripts/run_ti2v_extended_generation.py` | Paired generation for parent, joint extended repair, and factored extended repair |
| `scripts/verify_ti2v_repair_factorial.py` | Raw response, image-byte, budget, and decision replay checks |
| `tests/` | Synthetic checks without benchmark data or model calls |

The release contains a source snapshot plus a public proposal entry. `SOURCE_MANIFEST.json` records hashes; each remote experiment keeps its own frozen source manifest. Run from this directory to avoid importing same-named modules from the repository root. Upstream SkillAdam, model repositories, weights, data, and credentials are installed separately.

## Remote experiments

1. Prepare the complete case/seed manifest, preserving literal tasks, first frames, parent videos, and their hashes. The current development set has 20 cases and three seeds each; every arm retains all 60 records.
2. Freeze model revisions, sampling, budgets, source, and Git state. Validate each service's physical GPU and UUID. The controller runs with no visible GPU.
3. Run optimization or proposal generation under its declared protocol. Preserve rejected updates, abstentions, and unchanged records.
4. Freeze a new generation plan. Match model, input, duration, resolution, and seed across arms. Share generated bytes only when the full prompt, input, and generation settings match.
5. Freeze video selections before final scoring. Report both raw candidates and selected outputs; final scores do not feed the completed optimization run.

```bash
# On an authorized server, RUN is a newly prepared, frozen experiment directory.
# RUN/source holds this source package. Do not rerun an existing experiment.
CUDA_VISIBLE_DEVICES='' python3 scripts/run_ti2v_extended_generation.py \
  --root "$RUN" --stage generate
```

See [DEPLOYMENT.md](DEPLOYMENT.md) for dependencies and service contracts. Existing host checks require deliberate configuration for a different server. All model inference, benchmark experiments, and evaluation run remotely.

## Scope and ownership

The current generation work keeps the original five video gates, selector, and EWMBench scorer fixed. Human review is excluded; evaluator improvements belong to collaborators. The historical event-sampling ablation is retained as completed evidence and is not being restarted.

Exact revisions are in [configs/model-pins.json](configs/model-pins.json). Generation is restricted to MiniMax/JoyAI; the reported runs use MiniMax-H3, with no JoyAI comparison. Full public-benchmark coverage, matched strong baselines, and independent confirmation remain necessary for a SOTA claim.
