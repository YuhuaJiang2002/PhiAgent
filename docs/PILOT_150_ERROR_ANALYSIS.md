# 150 条批量质检误差分析

结果文件：`/data1/zhn/ego_qc_runs/pilot_150/ego_qc_pilot_150.xlsx`。

本批使用 `doubao-seed-2-0-mini-260428`，视频临时降为 480p/2FPS，保留原始时间轴；共 150 条，人工有效 50 条、人工无效 100 条，API 成功 150/150。

## 1. 与原始 episode 审核的混淆统计

| 人工审核 | 模型 valid | 模型 invalid | 模型 needs_human_review |
| --- | ---: | ---: | ---: |
| valid（50） | 49 | 1 | 0 |
| invalid（100） | 47 | 42 | 11 |

因此，按原始平台标签直接比较：

- 状态一致率：91/150 = 60.67%；
- invalid 严格召回率：42/100 = 42.00%；
- invalid 精确率：42/(42+1) = 97.67%；
- valid 误删率：1/50 = 2.00%。

这组数字不能单独解释为 Prompt 的能力，因为原始平台口径是整条 episode 审核，而当前 Prompt 同时允许“首尾 bad 可裁剪后保留 valid”。两种口径应分别评估。

## 2. 主要问题

### 2.1 任务指令缺失

150 条中有 99 条 episode 的 `meta/episodes.jsonl.tasks` 没有可用任务文本，只包含 `bad` 或 `bad(原因)`；这 99 条全部是人工 invalid。当前试验在这种情况下仅把任务类别传给模型，导致模型容易把“完成了看起来像该类别的动作”误判为 valid。

改进方式：从 `meta/tasks.jsonl` 过滤出候选任务文本，并优先通过 `task_index` 与 episode 对齐；无法对齐或候选冲突时，输出 `task_instruction_status=ambiguous` 和 `needs_human_review`，不应强行 valid。

### 2.2 缺陷扫描没有独立于任务完成

人工 invalid 中，模型误判 valid 的数量如下：

| 人工无效原因 | 样本数 | 模型 valid | 模型 needs_human_review |
| --- | ---: | ---: | ---: |
| 其他 | 34 | 18 | 7 |
| 未按要求完成任务 | 27 | 10 | 2 |
| 采集设备屏幕露出 | 15 | 10 | 1 |
| 包含多余动作 | 5 | 5 | 0 |
| 发生意外干扰 | 7 | 1 | 0 |
| 全程静止无动作 | 9 | 0 | 1 |
| 手部露出少 | 1 | 1 | 0 |
| 视频模糊不清 | 2 | 2 | 0 |

模型常见模式是“主体任务完成，因此 valid”，然后把屏幕、耳机、平板、额外动作或结尾设备操作忽略为正常准备/收尾。需要先做独立质量门禁扫描，再做任务完成判断；质量缺陷不能被任务完成覆盖。

### 2.3 原始 tasks 与任务类别存在冲突

同一 `collection_task_name` 下可以出现不同的 clean task，例如“实验室试管”下同时出现药箱和试管指令，“水果篮封膜”下出现试管指令。这说明任务类别、episode tasks 和 `meta/tasks.jsonl` 不是同一层级的数据，不能仅按 collection task ID 盲目填充任务文本。

应优先恢复 episode 的真实 `task_index`；如果暂时无法解析 parquet 或平台记录，就把候选列表和冲突状态传给模型，并将该样本纳入人工复核。

### 2.4 采样过粗

本批为了覆盖 150 条使用了 480p/2FPS 单次整段调用。短暂露屏、摸鼻子、摘耳机、手部出画和中间断点可能只存在少数帧，粗采样会降低召回率。正式自动筛选应采用：

1. 480p/2FPS 粗扫全片；
2. 对风险窗口、首尾和任务切换处用 720p/6～8FPS 复核；
3. 对主体任务中间的风险窗口禁止用剪切拼接恢复 valid。

## 3. 下一版建议

1. 在输入中增加 `task_instruction_status`、`task_instruction_candidates` 和来源字段；
2. 输出独立的 `quality_gate_evidence`，强制覆盖屏幕、人脸、隐私、模糊、静止、手部和额外动作检查；
3. 同时输出 `platform_review`（严格整条审核）和 `crop_policy_review`（首尾可裁剪口径），分别与不同真值比较；
4. 对 `missing`/`ambiguous` 任务指令默认 `needs_human_review`，除非存在明确的致命质量问题；
5. 用 10～20 条覆盖屏幕、额外动作、静止、模糊、任务未完成的样本做高质量 720p/8FPS 复测，再决定是否重跑全部 150 条。
