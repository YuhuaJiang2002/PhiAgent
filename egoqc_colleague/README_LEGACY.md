# egoqc —— Ego 采集数据自动质检

用本地 **qwen3.8-27b-fp8**（8 卡 vLLM）对采集的 ego 视频做**二元判定**：有问题→删除 / 没问题→保留。

## 目录

| 路径 | 内容 |
|---|---|
| `qc_run.py` | 质检流程主脚本（抽帧 → 提示词 → 推理 → 反证审计 → 代码聚合 → 指标） |
| `preds_<tag>.jsonl` | 逐条判定结果：模型原始回答、证据帧、触发规则、耗时、token、**提示词版本与哈希** |
| `metrics_<tag>.json` | 每轮指标（召回/精确/误删/按原因召回） |
| `prompts/<version>.txt` | 每次运行使用的完整提示词存档 |
| `docs/` | 设计与分析文档（规范解析、问题排名、迭代结论、日报等） |
| `HANDOVER.md` | **★ 完整交接档案**（环境/资产/13 轮迭代/已证伪方向/下一步）。含凭据，已 gitignore，不入库 |
| `HISTORY.md` | 版本对照与关键结论 |
| `frames/`、`logs/` | 已 gitignore（可由代码重新生成） |

## 运行

```bash
# 前置：8 个 vLLM 实例监听 18090-18097
cd /data1/review/egoqc
python3 qc_run.py --limit 100 --workers 24 --tag run100_v11
```

## 版本管理约定

1. **每轮迭代 = 一次 commit + 一个 tag**（`v11`、`v12`…）
2. 提交前必须递增 `qc_run.py` 里的 `PROMPT_VERSION`
3. 每条结果自带 `prompt_version` + `prompt_sha`，可反查是哪版提示词判的
4. 结果文件与代码同提交，保证"指标 ↔ 代码"可对应

```bash
git add qc_run.py preds_run100_v11.jsonl metrics_run100_v11.json prompts/v11.txt
git commit -m "v11: <改动> —— 召回xx% 误删xx%"
git tag -a v11 -m "<结论>"
```
