# 质检流程 v23 版本说明

日期：2026-09-22 ｜ 脚本：`/data1/review/egoqc/qc_run_v23.py` ｜ 提示词存档：`prompts/v23.txt`

## 一、先纠正版本号约定（v23 这个号是怎么来的）

之前 `qc_run_v3.py` 的命名是错的。服务器上同时存在两套编号，被混进了一个文件位置：

| 轴 | 含义 | 取值 |
|---|---|---|
| **提示词 / 流程版本** | 改提示词、改抽帧、改聚合规则时递增 | v12 → v13 → … → v21 → v22 → **v23** |
| **数据集** | 换数据时变 | mixed150 → 142_v3 → **balanced_5x100_v2** |

`qc_run_v3.py` 里的 `v3` 指的是**数据集**（`cus000001_ego_qc_142_v3`），但别的文件里 `v12~v22` 指的是**提示词版本** —— 同一个位子放了两种含义。

**所以「v4」是错的**：既不是提示词第 4 版（早过了），也不是第 4 个数据集（不存在）。

**v23 才是正确的下一个号**：承接提示词血缘 v22。

## 二、版本号与数据集解耦

从 v23 起，**一个脚本 + 数据集参数**，不再一个数据集复制一份脚本：

```bash
QC_DATASET=set01 python3 qc_run_v23.py ...     # set01 ~ set05
# 或
QC_DATASET_ROOT=/任意/路径 python3 qc_run_v23.py ...
```

结果文件名自带数据集与提示词版本：`preds_set01_v23.jsonl` / `metrics_set01_v23.json`。

| 新判据 | 落到哪 | 具体 |
|---|---|---|
| 光线过暗 | **q3** 画面质量 | 选项加 `光线过暗` |

| 手部可见度 | **新增 q6** | `手部全程可见 / 经常不可见 / 几乎不可见 / 无法判断` |

`decide()` 新增 4 条聚合规则：`too_dark` / `lighting_change` / `hair_occlusion` / `hand_visibility`。

### 【C】豁免窗口：**明确不读 `segment_index.csv`**（重要）

新数据集提供了 `segment_index.csv`，含每个片段的 `开始秒 / 结束秒 / 状态（保留 / 分隔丢弃）`。
初看这是"逐条精确豁免窗口"，比写死 2 秒好得多。**但实测发现它构成标签泄漏，不能用：**

```
有效 · 有保留片段   250
无效 · 整片丢弃     239
无效 · 有保留片段    11
─────────────────────────
用「有无保留片段」预测「有效」的准确率 = 97.8%
```

- **250 条有效样本，全部都有保留片段**
- **250 条无效样本，239 条是整片丢弃**

也就是说 `分隔丢弃` 状态 ≈ 标签本身。而且它**只存在于 `manifest.pending.jsonl`（评测文件）**，
**不在 `inference_inputs.pending.jsonl`（模型输入文件）** —— 造数据的人也是把它当评测数据而非输入。

**故：豁免窗口继续沿用口径「首尾各 2 秒」，不逐条读平台片段。**

> 遗留问题：如果生产环境实际是按平台片段裁剪的，那模型的 2 秒假设就永远对不齐。
> 这需要确认生产环境的裁剪规则。
