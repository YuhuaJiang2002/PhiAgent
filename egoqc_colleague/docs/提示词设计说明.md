# 提示词问答的「设计说明」——问题是怎么被设计出来的

> 说明对象：`测评流程与内容设计_v3.md` 第四部分的 5 组问题
> 核心方法：**不从规范照抄，而从实测数据反推**

---

## 一、第一原则：问题数量由数据决定，不由规范决定

规范有 27 条无效原因，但我**没有**设计 27 个问题。因为实测的删除原因分布极度集中：

| 排名 | 问题 | 占比 |
|---|---|---|
| 1 | 设备/平板/手机/屏幕/腰包 露出 | **52.2%** |
| 2 | 任务未按要求完成 | **26%** |
| 3 | 视频模糊 | **16%** |
| 4 | 抖动/静止/多余动作/无意义动作 | 各 1–3% |
| 5 | 人脸 | **0.5%** |

**前 3 项覆盖 94%。** 所以设计 5 组问题就够，剩下 22 条规范要么并进这 5 组，要么根本不用做（人脸只占 0.5%）。

> 这一步的关键证据是：我把平台原因字段（100% 覆盖但粗）+ bad 文本里**手写的原因**（只有 30% 覆盖但很细）交叉统计，才发现"其他"里 34% 其实全是设备问题 —— 真实第一问题的占比从 37% 修正到 **52%**。

---

## 二、七个设计原则（每条都在防一种 VLM 已知失效模式）

| # | 原则 | 防的是 |
|---|---|---|
| 1 | **封闭选项**，不给自由发挥 | 问"有没有问题"，模型会答"看起来还可以" |
| 2 | **强制帧 ID 证据** | 幻觉。rve 源码里的说法很到位："合法帧号只证明引用存在，不证明帧内容支持主张" |
| 3 | **强制反证** | 模型一律判"通过"的退化倾向 |
| 4 | **覆盖度声明 + "无法判断"免责** | 模型假装看全了；只采 20 帧却宣称"全程没出现设备" |
| 5 | **一次只问一条，禁止下总论** | 多问题混答时互相冲淡；也把结论权收回给代码 |
| 6 | **任务道具豁免** | 把任务要求操作的平板误判为"设备露出" |
| 7 | **技术指标转成可观察判断** | VLM 对"模糊""抖动"没有绝对标尺 |

---

## 三、逐个问题的推导过程

### 3.1 问题 1：设备露出（52%，最关键）

**原始信息有三种，且互相不完全一致：**

| 来源 | 内容 |
|---|---|
| 平台标签 | 「采集设备屏幕露出」（1722 条） |
| 手写文本 | 「平板一直在视频画面中」204、「漏手机了」113、「漏平板」90、「露腰包了」24… |
| 你的澄清 | 是**操作员身上佩戴**的录制装置；桌上那个小东西也是设备 |

**推导：这个标签名有歧义** —— "屏幕"？"设备"？"身上"？三者不是一回事。
所以我把它拆成 **5 个必须逐项回答的子问题**：

```
1. 有没有？        → 四选一（未出现 / 疑似 / 明确出现 / 无法判断）
2. 是什么？        → 设备本体 / 设备屏幕 / 小型设备
3. 在哪？          → 下边缘 / 左下 / 右下 / 左侧 / 右侧 / 中央
4. 多大？          → <2% / 2–10% / >10%
5. 反证            → 哪些帧没有
```

**为什么要问"在哪"和"多大"？** —— 这是**交叉校验**设计：

> 设备戴在**身上**，ego 视角里它必然出现在**画面下缘或两侧**，而且通常很小。
> 如果模型报"出现在**中央**、占比 >10%"，那它极可能把**桌面上的任务道具**当成了设备。
> 位置 + 占比 + 是否任务道具，三个信号互相印证，能自动暴露这类误判。

**为什么必须写"任务道具豁免"？** —— 因为实测有任务描述原文就写着：

```
王乾坤数据线收纳：左手按压放置在白色收纳架上的平板电脑屏幕,右手在持握白色耳机。
```

不写豁免，这个任务的所有样本都会被误判成"设备露出"。

**为什么强调"只露一角也算"？** —— 因为标注口径是"出现即无效"（实测 4657 条无效的坏片段全是 100%），严宽度必须和人工对齐，否则召回上不去。

### 3.2 问题 2：任务未按要求完成（26%）

**可用的上下文**（实测）：114/154 个数据集有真实任务描述；`collectionTaskSop` 字段全空，不能用。

**任务描述的实际形态**是"动作指令式"的，例如：

```
积木收纳       ：将散落在桌面或收纳区的积木、玩具模块按颜色或形状分类,逐一放入对应的收纳托盘中,确保每个模块归位整齐
李学臣医药箱整理：打开医药箱,取出并检查每种物品的保质期,然后放入,再检查下一个,最后扣上盖子
张东玉积木收纳  ：左手扶住形状配对桶,右手持粉色块状积木调整角度对准桶盖孔洞,尝试放入未成功
```

**推导：这类描述蕴含三类判据** —— 动作类型 / 操作对象 / 终态要求。所以问题按这三类来问，并把措辞锚定在"能看到什么"：

| 措辞 | 防的错误 |
|---|---|
| "**准备动作（伸手、对准、靠近）不算完成**" | 模型把"伸手过去"当成完成任务 |
| "**放入/归位必须看到物体被放置并停稳，仅手持不算**" | 只看到夹持就判完成 |
| "**若描述本身写着'尝试但未成功'，则该任务就是尝试，不得据此判失败**" | ⚠️ **实测真有这样一条描述**（张东玉积木收纳原文就是"尝试放入未成功"）。不写这条，该样本必错 |
| "**不要因为视频结尾突然停止就判未完成，除非终态明显与描述不符**" | 模型把"视频截断"当成失败证据 |

> 注意最后一条和第三条都是从**真实任务描述文本**里挖出来的，不是凭空想的。这就是"从数据反推"的具体含义。

---

### 3.3 问题 3：视频模糊（16%）

规范原文是"光线过暗或过亮，**看不清手部动作**算无效"。这里有两个设计动作：

1. **不给"模糊/不模糊"二分，给五级分类**
   因为 VLM 对"模糊"没有绝对标尺。分级（清晰 / 轻度 / 严重 / 中心区域 / 画面发白）把连续的模糊度切成可选项，模型只需做相对判断。

2. **锚定在"手部动作是否可辨"，而不是"画面是否模糊"**
   这把一个主观的、与任务无关的判断，转成**与任务相关的可观察判断** —— 模型更容易对齐，也和规范原意一致。

3. **单独列出"中心区域模糊"**
   规范 2.26 单列了这一类，实测"中心区域模糊"在手写文本里出现 **256 次**（是手写原因里最高的一项），说明它是独立且常见的模式。

---

### 3.4 问题 4：时序类与无意义动作（5%）

**这里有个物理限制必须先解决**：**均匀取帧判不了抖动，也判不了"长时间静止"** —— 静止和抖动都需要帧与帧之间的变化信息。所以：

- 输入上加 **3 段连续帧**（每段 8 帧，间隔 0.1s）
- 判定上给 **"超过 10 秒"** 这个量化门槛（来自规范 2.11 原文"超过 10s 的静止画面"）

**"无意义动作"的具体列举也不是我编的** —— 是从 bad 文本里挖出来的高频项：

```
摸鼻子 34 次、废弃/废 39 次、勾手腕 20 次…
```

规范 2.11 原文列举的是"休息、聊天、扶头环、玩手机、抓痒、摸鼻子"，我把实测高频项补了进去。

---

### 3.5 问题 5：人脸（0.5%）

只占 0.5%，所以只问最简单的三选一。但补了一句"**含镜面反射、照片、屏幕中的人脸**" —— 这是防漏（规范 2.5 原文是"禁止录入任何人脸"，宽严度很严）。

## 四、问题之间的边界处理

设计多个问题时，最容易出的错是**边界重叠导致重复计分**。我做了这几处隔离：

| 边界 | 处理 |
|---|---|
| 设备 vs 任务道具 | 在 Q1 里写豁免条款（唯一能区分的地方） |
| 设备 vs 人脸 | 明确 Q1 不管人脸，人脸单列 Q5 |
| 模糊 vs 中心区域模糊 | Q3 里作为**并列选项**，不叠加判定 |
| 抖动 vs 无意义动作 | Q4 里用多选 flags，各自独立触发不同规则 |
| "其他"无法归因 | 不进任何问题，聚合时单独走 `needs_human` |

另外还有一条全局隔离：**模型不做总论**。每组问题只回答自己那条，最终 `keep/delete` 由代码按硬规则聚合。这既避免了"模型综合判断时被强特征带偏"，也让每次误判都能归因到具体哪条规则。

## 五、输出结构的设计

为什么用嵌套 JSON 而不是自然语言：

1. **聚合要代码做** —— 模型只提供"判断 + 证据 + 置信度"，`delete` 由代码按硬规则得出（rve 的核心经验：模型输出只是自检值，确定性代码会重新计算并覆盖）
2. **每条判定必须绑定帧 ID** —— 便于人工事后核查证据是否真的支持
3. **`coverage` 字段** —— 记录"我看了多少帧、有没有覆盖全程"，这是"无法判断"的依据，也是排查"漏检是不是因为抽帧不够"的线索

## 六、反证审计的问题设计（防幻觉核心）

对判"删除"的条目再问一次。措辞经过三次迭代才定：

| 版本 | 措辞 | 问题 |
|---|---|---|
| v1 | "请复核这个判定" | 模型会橡皮图章说"确认" |
| v2 | "请找证据推翻这个判定" | 模型会**硬找**出假反驳（为了完成任务） |
| **v3（采用）** | "请主动寻找能推翻的证据；**若核对后认为判定成立，必须明确写'未找到反驳证据'，不得为了反驳而编造**；每条反驳必须绑定帧 ID" | 两个方向都堵住 |

## 七、还没定稿的部分（需要你）

**问题 1 目前是"盲写"状态。** 我按你的澄清 + 我的观察写了描述（深色、随身佩戴、出现在画面下缘），但**没有样例帧锚定**，所以：

- 如果实际设备是**浅色**的，描述会误导模型
- 如果它通常出现在**画面中央**（而非下缘），"位置"设计的交叉校验会失效

**解法**：给我 **3–5 张"设备露出"的样例帧**，我挑 2–3 张作为**少样本锚定**放进提示词。这是提升问题 1 召回最有效的一招 —— 比改一百句措辞都管用。

其余 4 个问题的设计依据都已实测确认，可以直接定稿开跑。
