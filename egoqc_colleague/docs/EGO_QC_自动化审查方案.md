## 一、规范到底定义了什么样的"合格"

### 1.1 三层判定（这是最容易被忽略的地方）

规范不是二分类，而是**三态**：

| 判定 | 含义 | 后果 |
|---|---|---|
| **有效** | 完成预定任务，且画面/隐私/稳定性均合格 | 整段保留 |
| **有效但部分片段 bad** | 整条有价值，但开头/局部有不可用片段 | **bad 片段将被切除**，其余保留 |
| **无效** | 不满足审核要求 | 整条丢弃，并选择无效原因 |

**关键点：`bad` 不是"无效"的同义词。** 规范 1.2 明确列了 4 种"整条有效但需切掉局部"的情形：
a. 开头 >2s 手部未出现（单手可以）；b. 开头有 10s 无关/无意义片段；c. 一个视频含多个任务 → 短的标 bad、最长的做正常标注（且连续多个视频必须选相同的片段）；d. 开头出现人脸画面（可保留无脸片段）。

### 1.2 27 条无效原因（2.1–2.27）按性质分四类

| 类别 | 条目 | 特征 |
|---|---|---|
| **A 隐私与合规** | 2.1 非第一人称 / 2.4 拍到地址手机号 / 2.5 拍到人脸 / 2.6 拍到手机平板 | 语义，需检测/OCR |
| **B 画面质量** | 2.8 遮挡 / 2.9 画面颠倒 / 2.10 闪烁冻结黑屏 / 2.12 光线过暗过亮 / 2.20 过热模糊 / 2.22 四角固定阴影 / 2.25 手距镜头过近 / 2.26 中心区域模糊 / 2.27 光线变化明显 | **大多可测量**，CV 指标可解 |
| **C 动作与内容** | 2.2 双手出画>2s / 2.3 走动时手与道具露出规则 / 2.7 无实际意义 / 2.11 >10s 静止或无关动作 / 2.15 手部露出少 / 2.16 抽烟喝水吃东西 / 2.17 重复动作刻意演示 / 2.18 画面抖动 / 2.19 道具不在视野 / 2.21 丢帧 / 2.23 抬头转头回应他人 / 2.24 勾手腕 | 信号+语义混合 |
| **D 采集指导（不是审核判据）** | 2.13 尽量迎光 / 2.14 场地灯光 / 2.24–2.25 的坐姿建议 / 2.2 扶头环调节 | ⚠️ **做自动审必须剔除**，否则会误判 |

### 1.3 流程与抽检

- **审核**：逐条从头看到尾（可倍速、不可快进）→ 不达标标"无效"并选原因 → 无效视频也要标 `bad` 文本。
- **抽检**：需求方对标注结果人工抽检 **≥5%**，结果在平台标"通过/不通过"，**通过率不得低于 50%**。
- 平台"审核状态"有 4 个取值：有效 / 无效 / **待确认** / **未审核**。

### 2.2 平台字段 ↔ 规范概念（全部实测确认）

| 规范概念 | 平台接口字段 | 实测值 |
|---|---|---|
| 审核状态 | `auditStatus` | `valid` / `invalid` |
| 无效原因 | `auditInvalidReason` | 21 项之一 |
| 待确认 | `auditStatusStats.uncertain` | 项目级 9 条 |

### 2.3 ⚠️ 我构建的 `cus000001_mixed150` 的缺口（已实测）

我只保留了 episode 级的 `valid/invalid`，**丢掉了段级信息**。在选中的 150 条上实测：

| 项 | 数量 |
|---|---|
| 审核 valid | 50 |
| ├─ **含 bad 子片段（按规范必须切除）** | **48** |
| └─ 全程干净无 bad | **2** |
| 审核 invalid | 100 |
| 全数据集 bad 片段时长占比 | **63.8 / 265.6 分钟 = 24.0%** |

**结论：按规范口径，这个数据集里 24% 的视频内容是"必须切掉"的，但当前清单无法表达。** 如果直接拿去训练，会把 24% 的污染片段当成正样本。这不影响它作为**审核任务**的训练集（标签本身没错），但作为**数据交付物**是不完整的。

## 四、和 `rve` 项目的关系：能复用骨架，不能复用模型

| 维度 | rve（现状） | 质检审查（目标） |
|---|---|---|
| 评什么 | **生成**的机器人视频，任务完成质量 | **真实采集**的 ego 数据，采集合规性 |
| 判据来源 | 原子契约（pass/partial/fail + 必需正面证据） | 规范 27 条（同构！） |
| 手段 | LangGraph 状态图、并行 Agent、条件仲裁、盲测 | 应以确定性 detector 为主、VLM 为辅 |
| 打分 | 确定性 0–100，门控因子乘原始分 | 三态判定 + 原因 + 建议切除区间 |
| 可观测 | Langfuse 逐 Agent 证据链 | 同样需要证据链 |
| 资源 | qwen3.8-27b-fp8 / GPU | 语义层可复用同一模型 |

**可以直接复用的**：原子契约的表达方式（`pass/partial/fail` + 最低正面证据要求）几乎能 1:1 映射规范条目；证据链与 Langfuse 观测；盲测隔离（标注员/审核员不应看到真值）；确定性打分引擎的"门控因子"思想适合做"一票否决"（如人脸出现直接无效）。

**不应该复用的**：rve 的评分模型与任务卡（那是"任务做得好不好"，不是"采集合不合规"）；rve 的 0–100 分制（质检要的是三态 + 原因，分数无意义）。

**建议**：新建独立项目，**借用 rve 的契约/证据/观测骨架**，检测层完全重写。

## 五、建议的项目架构

```
/data1/review/egoqc/            （新项目，与 rve 并列，互不影响）
├── contracts/                  27 条规范 → 原子契约 YAML/JSON
│   ├── capture_quality.yaml    2.8/2.9/2.10/2.12/2.20/2.22/2.25/2.26/2.27
│   ├── action_content.yaml     2.2/2.3/2.7/2.11/2.15/2.16/2.17/2.18/2.19/2.21/2.23/2.24
│   └── privacy.yaml            2.1/2.4/2.5/2.6
├── detectors/                  确定性检测器（每条规则一个，纯函数 + 阈值可配）
│   ├── frame_quality.py        亮度/色温/清晰度/闪烁/冻结/四角阴影
│   ├── motion.py               IMU 抖动、静止检测、丢帧
│   ├── hand_presence.py        手部出画/露出率/过近/勾腕（用 mano + keep_frame）
│   └── privacy.py              人脸检测、手机平板检测、OCR
├── semantic/                   VLM 语义层（多帧采样 + 结构化输出 + 证据帧）
├── engine/                     规则引擎：detector/semantic 结果 → 三态判定 + 原因 + 切除区间
├── pipeline/                   批量编排（复用 rve 的并行/断点/恢复思路）
├── eval/                       与人工标注对齐的评估（混淆矩阵、按原因召回）
└── reports/                    逐条 JSONL + 汇总报告
```

**输出格式建议**（每条）：

```json
{
  "dataset_id": 9650, "episode_index": 4,
  "verdict": "invalid",                     // valid | valid_with_cut | invalid
  "reasons": [{"label": "视频模糊不清", "confidence": 0.83, "evidence": {"frames": [12, 340], "metric": "center_lap_var=18.2", "threshold": 40}}],
  "cut_segments": [],                       // verdict=valid_with_cut 时给出 [{"startSec":343.589,"endSec":345.9}]
  "needs_human": true,                      // 低置信度交人工（预筛定位）
  "contract_results": [{"id":"2.26","result":"fail","evidence":[...]}]
}
```

**关键设计取舍**：先做"**预筛/排序**"而不是"自动定论"——把明显违规的挑出来排在前面，人工只看被标记的，标注员效率立刻提升，风险也低。等按原因的召回率达标后再放开自动判定。

## 六、评估设计（这里有个陷阱）

**陷阱：`cus000001_mixed150` 不能当泛化测试集。** 它是从 28 个"valid≥5 且 invalid≥10"的合格任务里、按 50/100 配比抽的，存在双重选择偏差。它适合做**回归集**（每次改算法跑一遍看有没有退化），不适合报"准确率"。

**建议另建分层测试集**：从项目 7 全量 **8756 条**中按 21 个原因分层抽样 300–500 条，保证长尾原因（如"视频模糊不清"在项目级只有 484 条、"手部露出少"更少）都有足够样本。

**指标**：
- 按原因的 **召回**（漏检 = 脏数据进训练集）与 **误报率**（误判 = 好数据被删，代价更高）
- 三态一致率（尤其 `valid` vs `valid_with_cut` 的区分——这是规范特有维度）
- 与人工审核的 **Cohen's kappa**，而不是单纯准确率
