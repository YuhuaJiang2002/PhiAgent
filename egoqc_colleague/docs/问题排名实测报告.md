- ✅ **对均匀取帧方案是好消息**：既然是整条判废，均匀采样理论上能覆盖到

## 四、实测验证：均匀取帧能否看到第 1 大问题？

我抽了 2 条"采集设备屏幕露出"的样本（`20260830T1880-C149` ep62 / ep74），各均匀取 9 帧拼图查看；再取同数据集的一条**有效**样本（ep0）作对照。

**结果：在 18 张均匀帧里，我都没有明确看到"屏幕"。**

- 有效样本的画面更"贴近桌面"（只有桌面 + 手 + 红碗 + 积木）
- 无效样本画面更"开阔"，能看到更多环境（墙面、桌腿、身体），底部中央有一个灰色物体

**这说明"采集设备屏幕露出"的视觉特征尚未明确**，可能的原因：
1. 屏幕只在极短时刻出现，均匀取帧漏掉了
2. 屏幕在画面底部边缘、尺寸很小，低分辨率下看不清
3. 画面更"开阔"本身才是判据（相机角度/佩戴方式不对）

**⚠️ 这是当前最大的未知风险**：第 1 大问题（占一半）如果视觉特征不清楚，LLM 判不准，整个方案的天花板就锁死了。

**建议先做一件事**：拿 10–20 条"采集设备屏幕露出"的样本，**高分辨率、密集取帧**（如每秒 1 帧看完整条），人工确认"屏幕到底长什么样、出现在哪、占多大"。这是设计 prompt 之前必须补的一课。

## 五、对"本地千问 + 均匀取帧 + 按要求判断"方案的直接影响

### 5.1 需要问的问题可以砍到 5–6 个（覆盖 ~94%）

| 优先级 | 问什么 | 覆盖 |
|---|---|---|
| **P0** | 画面中是否出现**平板 / 手机 / 发亮的屏幕 / 腰包 / 采集设备显示界面**？ | ~50% |
| **P0** | 是否**按任务要求完成了任务**？（需要任务 SOP 作为上下文） | ~26% |
| **P1** | 画面是否**模糊**（整体模糊 / 中心区域模糊 / 发白）？ | ~16% |
| P2 | 是否有明显**抖动**、**长时间静止**、**无意义动作**（摸鼻子、废弃测试片段）？ | 各 1–3% |
| P3 | 手部是否露出过少？ | 0.8% |
| **P4** | **人脸露出？** —— **只有 0.5%，优先级最低** | 0.5% |

### 5.2 对你方案的三点提醒

1. **人脸检测几乎没用**：全项目只有 22 条（0.5%）因人脸被删。你提到的"针对人的检测"投入产出比很低，除非是为了合规兜底。**真正该检测的是"屏幕/平板/手机"**。
2. **均匀取帧够用**（因为坏片段都是 100%），**但有一个前提**：第 1 大问题的视觉特征必须能被看清。建议取帧分辨率别压太低 —— 我在 400px 宽下没能确认屏幕，实际推理建议至少 768–1024px 宽，必要时对**画面底部区域**单独裁剪放大。
3. **"未按要求完成任务"占 26%，必须给任务 SOP**：这条光看画面判不了，需要把该 episode 的任务描述（`meta/tasks.jsonl` / `meta/episodes.jsonl` 里的 task 文本）一起喂给模型。这也是 rve 里 `task_card` 机制的价值所在。

### 5.3 一个可操作的验证方法

拿已有的人工标注做**回归测试**：从 4657 条无效 + 3538 条有效里分层抽样（每个原因 30–50 条），用你的本地千问跑一遍，统计**按原因的召回**。这样能立刻知道：
- 哪些问题模型能抓（预期：模糊、静止、明显任务失败）
- 哪些抓不到（预期：屏幕露出、抖动、丢帧）
- 抓不到的那些，再考虑用确定性的 CV 指标补
